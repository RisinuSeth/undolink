Expiring links with a clear deadline.

An expiring link is useful when a shared URL should stop working after a particular time. The key is choosing a deadline that matches the real task, while understanding what expiry changes and what it leaves untouched.

How does an expiring link work?

An expiring link is a URL that stops working through its redirect after a chosen time. The service checks the expiry when someone opens the link. If the deadline has passed, the redirect is no longer available.

UndoLink lets you choose from preset durations or set a custom date and time. The destination URL itself is not deleted or modified when the UndoLink redirect expires.

Choose a deadline people can actually meet

A useful expiry gives recipients enough time to complete the task without leaving the link active indefinitely. Think about when people will receive the link, their time zones, weekends or holidays, and whether they need time to return to it.

  • For a live event: allow time for late arrivals and follow-up information.
  • For a review: include the expected review window and a small buffer.
  • For a promotion: align the link deadline with the published closing time.
  • For a one-time handoff: consider whether a click limit is more appropriate than a long expiry.

Before sharing, double-check the date and time shown in the creation form. If recipients are in different time zones, state the deadline and time zone in your message too.

Expiry, scheduled starts and click limits are different

Expiry: when the link stops

An expiry sets the end of the period in which the redirect can be used. It is a time-based limit.

Scheduled start: when the link begins

A scheduled start keeps a link inactive until the selected start time. It is useful when you want to prepare a link before an announcement or release.

Click limit: how many uses are allowed

A click limit stops the redirect after the configured number of uses has been reached. This is a usage-based limit rather than a calendar deadline.

You can choose the control that best fits your goal. A link may need more than one rule—for example, a scheduled start and an expiry for an event announcement.

Examples of expiry settings

Registration closes on Friday

Choose a custom expiry after the registration deadline, with a little buffer for people who are finishing the form. Mention the closing time in the message where you share the link.

A resource for a short workshop

Set the link to start shortly before the workshop and expire after the planned follow-up period. If attendees need longer access to the actual file, configure permissions and expiry on the file platform too.

A limited number of invitations

If only a fixed number of visits should be allowed, a click limit may be more relevant than a short expiry. Consider whether repeat visits by the same person should count for your use case.

What happens after a link expires?

When an UndoLink redirect expires, visitors can no longer use that UndoLink URL to reach the destination through the redirect. The destination page or file remains where it was, and its own access rules continue to apply.

People may still be able to visit the destination directly if they know its address and the destination is publicly available. If the content itself must become unavailable, change its access or availability on the original hosting platform.

  • Expiry does not erase copies, downloads, screenshots, or messages.
  • Expiry does not remove the original page from the internet.
  • Expiry is not a substitute for revoking access in a cloud drive or document system.

Think of expiry as a deadline for the shared redirect—not a remote delete button for the destination.
